### motion-panels API notes (v0.4.0)

- `Group` forces inline `height:100%` / `width:100%` and `overflow: clip` on the
  outermost group only; `className` still layers flex rules on top.
- A `Panel` with `size` is sized; without `size` it fills. Only one sized panel
  per side, so a two-panel split must be one sized + one filling.
- `onSizeChange` fires **once per drag end** (not per frame) and reports in the
  unit the size was given — a number is pixels, `"30%"` is a percentage. Keep
  percentage sizes so panels refit when the container resizes.
- No imperative handle and no persistence helper: drive the fold with `collapsed`
  and persist sizes yourself.
- On a sized panel `...props` (including `className`) land on the **content**
  div, not the panel wrapper.
- `keepMounted={false}` unmounts collapsed content and runs the `exit` pose.
- Separator styling needs `relative` + `z-10` when neighbouring panels set their
  own z-index, otherwise the grip is painted over.

## Follow-up: no separator on the AI chat panel

Rafael asked to drop the separator there. Removed the `<PanelSeparator>` from
`__root.tsx` (which also made the `cn` and `PanelSeparator` imports unused).

The panel stays resizable: motion-panels renders its own bare drag edge
(`data-motion-panels-edge`, 8px mouse / 20px finger) whenever a sized panel has
no separator beside it. That element is unstyled, so nothing shows at rest — and
because it carries `data-resizing` / `data-crossing`, a drag guide line could be
added later with a single CSS rule if the affordance is missed.

## Investigated the table virtualization ("está ruim, travando")

Findings, in order of how much they cost:

1. **Hover prefetch storm (tables sidebar).** `TablesExplorerSidebar` fired
   `onPrefetchTable` on every row `mouseenter`/`focus`. That handler runs TWO
   queries (table details + first 50 rows), so scrolling the list with the pointer
   over it queued ~2 queries per row passed. Fixed with a 150ms hover-intent timer
   that is cleared on `mouseleave`/`blur`, so only the row the pointer settles on
   is prefetched.
2. **Wrong row estimate (tables sidebar).** `estimateSize: () => 30` against a real
   row height of 24px, with no `measureElement` — so rows were absolutely placed
   30px apart and `getTotalSize()` over-reported by 25%. Now measured per row via
   `ref={rowVirtualizer.measureElement}` + `data-index`, with the estimate
   corrected to 24.
3. **One base-ui `Popover.Root` per cell (data grid).** Every non-editing cell
   mounts `CellExpandPopover` — 730 lines, 1 `Popover.Root`, 4 `useState`, 1
   `useRef`, 5 `useMemo`, 2 `useEffect`. At 50 rows x N columns that is hundreds of
   roots, and they all re-render on every scroll frame because `useVirtualizer`
   lives in `TableDataEditor` (2272 lines) and `virtualItems` feeds
   `visibleEffectiveRows` (new array identity each scroll). NOT fixed yet — see
   below.
4. Removed `content-visibility: auto` + `contain-intrinsic-size` from the grid's
   `<tbody>` (a no-op on table internals, and misleading) and a dead
   `CellExpandPopover` import in `TableDataEditor.tsx`.
5. `TableDataEditor/hooks/useRowVirtualization.ts` is dead code (never imported);
   its logic is duplicated inline in `TableDataEditor.tsx`. Left in place.
