### motion-panels API notes (v0.4.0)

- `Group` forces inline `height:100%` / `width:100%` and `overflow: clip` on the
  outermost group only; `className` still layers flex rules on top.
- A `Panel` with `size` is sized; without `size` it fills. Only one sized panel
  per side, so a two-panel split must be one sized + one filling.
- `onSizeChange` fires **once per drag end** (not per frame) and reports in the
  unit the size was given — a number is pixels, `"30%"` is a percentage. Keep
  percentage sizes so panels refit when the container resizes.
- No imperative handle and no persistence helper: drive the fold with `collapsed`
  and persist sizes yourself.
- On a sized panel `...props` (including `className`) land on the **content**
  div, not the panel wrapper.
- `keepMounted={false}` unmounts collapsed content and runs the `exit` pose.
- Separator styling needs `relative` + `z-10` when neighbouring panels set their
  own z-index, otherwise the grip is painted over.

## Follow-up: no separator on the AI chat panel

Rafael asked to drop the separator there. Removed the `<PanelSeparator>` from
`__root.tsx` (which also made the `cn` and `PanelSeparator` imports unused).

The panel stays resizable: motion-panels renders its own bare drag edge
(`data-motion-panels-edge`, 8px mouse / 20px finger) whenever a sized panel has
no separator beside it. That element is unstyled, so nothing shows at rest — and
because it carries `data-resizing` / `data-crossing`, a drag guide line could be
added later with a single CSS rule if the affordance is missed.
