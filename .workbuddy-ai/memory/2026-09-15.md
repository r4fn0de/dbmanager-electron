## Duplo clique na row de tabela abre o editor

`src/features/database/components/TablesExplorerSidebar.tsx` (linha ~663).

Semântica que já existia e vale registrar:

| Callback | O que faz |
|---|---|
| `onTableSelect` (= `changeTable` no parent) | só seleciona/highlight a tabela |
| `onBrowseTableData` (= `handleBrowseTableData`) | `changeSchema` + `changeTable` + `changeSection("tables")` → abre o `TableDataEditor` |

O single click já chamava `onTableSelect`. Adicionado
`onDoubleClick={handleRowDoubleClick}` chamando `onBrowseTableData(tableTarget)`.
`tableTarget` (`{name, schema}`) já existia no corpo do map do virtualizer.

`handleRowDoubleClick` é declarado no corpo do map (não como arrow inline em JSX)
para não somar `noJsxPropsBind` — mas o Biome rastreia o binding local e **ainda
assim** flagra, então ficou +1 nessa regra (o arquivo já tem 36). Trade-off
aceito: legibilidade > regra que é falso-positivo com React Compiler ligado.

Detalhe: `onDoubleClick` no `<div>` da row, não no botão "..." de ações —
`stopPropagation` de `click` não impede o `dblclick` de borbulhar. Na prática o
dropdown abre no primeiro clique e o overlay captura o segundo, então não colide.

## Helper de tipo junto do editor inline no grid (Neon-style)

Rafael apontou o grid do `TableDataEditor`: duplo clique numa célula de
timestamp abria um `<Input>` de texto puro, obrigando a digitar
`2026-04-16T03:48:00.335Z` na mão. Pedido: "abrir junto com o editor inline",
como no Neon (calendário + `NULL`/`now`/`today`/`tomorrow`/`yesterday`).

### Arquitetura que já existia (importante)

| Peça | Papel |
|---|---|
| `TableEditorGridRows` `onDoubleClick` | chama `beginEditExistingCell` → input inline na célula |
| `CellExpandPopover` (botão ⤢) | editor por tipo completo: `datetime-local`, Monaco, toggle, validação, Save/Cancel |
| `table-editor-utils.ts` | `classifyColumnKind`, `validateDraft`, conversores datetime — **tudo já pronto** |
| `hooks/useInlineEditing.ts` | **código morto**, não é importado em lugar nenhum. O estado real (`editingCell`, `editingValue`, `persistEditing`, …) vive em `TableDataEditor.tsx` |

`Enter` numa célula focada também inicia edição inline (atalho de teclado
independente do duplo clique).

### Decisão de design

Primeira pergunta ao Rafael ofereceu 3 caminhos; ele escolheu "sempre o editor
do tipo (popover)". Depois corrigiu: **o widget do tipo abre JUNTO do input
inline**, não no lugar dele. O input inline continua sendo a fonte da verdade.

### Implementação

**`table-editor-utils.ts`** — adicionado no fim:
- `getInlineHelperKind(kind)` → `"timestamptz" | "timestamp" | "date" | "time" | "bool" | "uuid"` ou `null`.
  Exclui `json`/`array` de propósito: Monaco precisa de painel, que é o papel do `CellExpandPopover`.
- `getTemporalPresets` / `resolveTemporalPreset(kind, preset, now)` → texto canônico
  no mesmo formato que `normalizeDisplay` produz e `parseByType` aceita
  (ISO UTC p/ timestamptz, `YYYY-MM-DD HH:MM:SS` p/ timestamp, etc.).
- `draftToTemporalInput` / `temporalInputToDraft` — conversão canônica ↔ input nativo.

**`InlineCellHelper.tsx`** (novo, em `TableDataEditor/components/`):
- Popup do **base-ui direto** (`@base-ui/react/popover`), não o wrapper de
  `src/components/ui/popover.tsx`: o wrapper não repassa `anchor` para o
  `Positioner` (só `align`/`side`/`offset`), e eu preciso ancorar no input inline.
  `Positioner anchor={refDoInput}` + `Popup initialFocus={false}` p/ não roubar foco.
- `open` é fixo `true` e `onOpenChange` é no-op — quem manda é `editingCell`.
- Não é dono do valor: todo widget chama `onDraftChange` → `setEditingValue`.

**`TableEditorGridRows.tsx`**:
- `inlineInputRef` único (só uma célula edita por vez) anexado aos dois inputs inline.
- `<InlineCellHelper>` renderizado dentro da célula em edição.

### Três armadilhas que valem lembrar

1. **`onBlur` do input inline commita a célula.** Botões do helper usam
   `onMouseDown={e => e.preventDefault()}` para suprimir a troca de foco (mesmo
   truque que o dropdown de FK já usava). O widget temporal PRECISA de foco, então
   o `onBlur` do input foi guardado com `shouldKeepEditingOnBlur` (checa
   `relatedTarget.closest('[data-inline-cell-helper]')`).
2. **Furo que isso criava:** depois que o foco ia para o helper, o input inline já
   tinha blurrado — clicar em outra célula nunca commitava o draft. Fechado com
   `handleHelperBlur` no `Popup` (commit quando o foco sai do helper E do input).
   Commit duplo é inofensivo: `persistEditing` tem guarda `if (!editingCell) return`.
3. **Popover não pode ser renderizado dentro da célula sem portal.** A `TableCell`
   tem `truncate` (overflow hidden) e a `TableRow` tem `contain: layout` (cria
   stacking context) — qualquer painel inline seria cortado ou coberto pelas
   linhas seguintes. O `Portal` do base-ui resolve.

### Validação

- `tsc --noEmit` limpo.
- Lint: `InlineCellHelper.tsx` novo com 13 (`noJsxPropsBind` ×12 +
  `useFilenamingConvention` — ambas convenções dominantes do repo);

- **Atenção:** medir baseline copiando o arquivo de `HEAD` para `/tmp` dá números

## BUG: `Date` não tratado em `normalizeDisplay` (2 sintomas, 1 causa)

Rafael reportou depois de testar o helper: picker aparecia **vazio** e, ao clicar
fora do input sem digitar nada, a célula ficava marcada como alterada
("save/discard changes").

### Causa raiz (única)

O driver `pg` devolve **objetos `Date`** para `date`/`timestamp`/`timestamptz`.
Não há `setTypeParser` em lugar nenhum do repo, e `listPgRowsRaw` retorna
`rowsResult.rows` cru (sem mapping). `normalizeDisplay` caía no
`typeof value === "object"` → `JSON.stringify(date)` → string **com aspas**:

```
draft = '"2026-04-16T03:48:00.335Z"'   ← as aspas fazem parte do draft
```

Isso quebrava duas coisas de uma vez:

1. `utcIsoToDatetimeLocal('"2026-…Z"')` → `new Date` inválido → `""` → **picker vazio**.
2. `parseByType` testa `/^\d{4}-\d{2}-\d{2}/` no `trimmed` — a aspa inicial impede
   o match → cai no `return raw` (string com aspas). Comparado com
   `JSON.stringify(originalDate)` no `unchanged`, nunca bate → **falso "changed"**.

Efeito colateral grave: commitar uma célula de timestamp gravava a string **com
aspas** no banco (corrupção de dado real, não só cosmética).

### Fix 1 — `valueParsers.ts`

`normalizeDisplay` e `getCellTitle` ganharam branch de `Date` → `toISOString()`.
Com o ISO limpo o round-trip fecha: `normalizeDisplay(Date)` → ISO →
`parseByType(ISO)` → `new Date` → `JSON.stringify` iguais.

Verificado com `bun run /tmp/roundtrip.ts` (matriz valor→draft→parse→compare):

| Tipo | Antes | Depois |
|---|---|---|
| timestamptz / timestamp / date | FAIL | ok |
| time, bool, int, numeric, text, uuid, jsonb, int[], inet | ok | ok |
| **bytea** (Buffer) | FAIL | **FAIL** |
| **interval** (objeto do pg) | FAIL | **FAIL** |

`normalizeDisplay` também é usado no `rowKey` (`tableDataTransforms`), no export
CSV/JSON e no overlay da linha — todos melhoram (ISO limpo em vez de string
JSON com aspas). Ordenação por data também passa a comparar ISO.

### Fix 2 — guarda no `persistEditing` (type-agnóstica)

Para não deixar `bytea`/`interval` com o mesmo sintoma, e para cortar o problema
na raiz do fluxo: `TableDataEditor.tsx` ganhou `editStartValueRef`, setado em
`beginEditExistingCell` e `beginEditInsertCell` com o draft inicial. Em
`persistEditing`, se `editingValue === editStartValueRef.current`, chama
`cancelEditing()` e sai — **não houve digitação, não há o que persistir**.

Efeito bom de brinde: célula de linha de insert aberta e abandonada sem digitar
não grava mais `NULL` explícito na coluna (deixa o DEFAULT do banco agir).

### Correção de método (importante)

O baseline de lint copiando o arquivo de `HEAD` para `/tmp` é **inválido para
regras com inferência de tipo**. `TableDataEditor.tsx` acusou 106 no `/tmp` e 123
no projeto — os 17 de diferença eram todos `noUnnecessaryConditions`, que só roda
com tsconfig presente. Medido com um probe dentro do projeto
(`__baseline_probe.tsx` no mesmo diretório, rodado e apagado), o baseline real é
123 → **minhas mudanças adicionaram 0 erros**. Sempre medir com o arquivo dentro
do projeto.

## BUG: popup do helper não fechava ao clicar fora

Sintoma reportado depois do fix anterior. Causa: eu tinha fixado
`open` em `true` e passado `onOpenChange={() => undefined}`, ignorando o pedido de
dismiss.

### Como o base-ui fecha popovers (fato verificado no node_modules)

`PopoverRoot.js` monta `useDismiss(floatingRootContext, { outsidePressEvent: {
mouse: modal === 'trap-focus' ? 'sloppy' : 'intentional', touch: 'sloppy' } })`.
O `useDismiss` registra listeners **no `document`, em fase de captura**:

```
click / pointerdown / mousedown -> closeOnPressOutsideCapture
  -> store.setOpen(false, createChangeEventDetails(REASONS.outsidePress, event))
```

Para popover controlado isso chama `onOpenChange(false, { reason: 'outside-press' })`.
Nenhum `preventDefault` é feito nesse caminho. Escape usa
`reason: 'escape-key'` via listener de `keydown` no document.

### Por que NÃO basta honrar o `onOpenChange`

`useDismiss` decide "fora" com `isEventWithinFloatingTree(event)`, que só conhece
os nós registrados na floating tree. O input inline é passado via
`Positioner anchor`, **não** é `PopoverTrigger` — então o base-ui considera um
clique no próprio input como "fora" e commitaria a célula no meio da digitação.

### Fix

`InlineCellHelper.tsx` assume o dismiss com listener próprio em `document`
(`pointerdown`, capture). Ignora o press se o alvo for `anchor.current` (o input
inline) ou estiver dentro de `[data-inline-cell-helper]`; caso contrário chama
`onCommit()` — que é o que encerra a sessão (`persistEditing` → `cancelEditing` →
`editingCell` null → o grid para de renderizar o helper → popup some).

O `onCommit` vai para um `commitRef` atualizado num `useEffect` sem deps, para o
listener não ser re-inscrito a cada render (o grid passa closure nova sempre).

O `handleHelperBlur` no `Popup` continua, cobrindo saída de foco por teclado
(Tab) sem press.

### Ordem de eventos (conferida)

Press num preset: `pointerdown` (fora do guard? não — está dentro do helper) →
`mousedown` com `preventDefault` (não rouba foco) → `click` aplica o valor. OK.
Press em outra célula: `pointerdown` → commit → `click` na outra célula. OK.
`preventDefault` em `mousedown` NÃO cancela o `pointerdown`, que vem antes — por
isso o guard não pode depender só do `preventDefault`.

## Borda azul em volta do grid ao selecionar uma row

`TableEditorGrid.tsx` tinha no container do scroll:

```
h-full overflow-auto focus-within:ring-2 focus-within:ring-ring/40 focus-within:ring-inset
```

A `<table>` tem `tabIndex={0}` (necessário para o `handleTableKeyDown`), então
**qualquer clique dentro do grid foca a tabela** → `:focus-within` no container →
borda em volta de tudo.

Trocado por `has-[>table:focus-visible]:*` (3 classes), que só acende quando a
própria `<table>` tem foco de teclado. Motivo de não remover de vez: a `<table>`
tem `focus-visible:outline-none`, então sem isso um Tab para dentro do grid
ficaria sem indicador de foco algum (WCAG 2.4.7). Célula focada já tem o próprio
anel (`ring-2 ring-primary/40 ring-inset`), mas só depois que `focusedCell` é
setado.

Compilação da variant verificada com `@tailwindcss/node` — ver receita no
`MEMORY.md`. Seletor gerado: `:has( > table:focus-visible)`.

## Seleção de texto: default passou a ser `none`

### Diagnóstico

em nenhum desses arquivos.
